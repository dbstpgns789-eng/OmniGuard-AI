# 04. 현장 사고 영상에 빠른 경로 오버레이 (탐색 실험, 실패 기록)

> 이 실험은 변인을 통제한 실험이 아니다. "현장 영상에서 화면이 어떻게 나오고 어디서 깨지는가"를 보려는 탐색이며, 수치를 성능 근거로 쓰지 않는다.

## 질문

1. 영상에 주의·감속·정지를 얹은 화면이 의도대로 만들어지는가.
2. 실제 사고 영상에서 사고 전에 정지가 뜨는가.
3. (개선 1) 바닥 기준 거리로 2D 겹침 오판을 줄일 수 있는가.

## 조건

- 영상: iSafetyBench `0QHQ2nmdE78_clip0_trim_4·7·8` (롤 권취기, 빨간 상의 작업자가 가동 중 조정하다 말려 들어감). 뉴스 편집본, 세로로 잘림, 자막, 8번부터 모자이크
- 포즈: rtmlib `Body` lightweight, 노트북 CPU. 가동 여부는 켜짐으로 고정
- `overlay.py`(개선 전): 맞물림선 기준 띠 3개를 화면에 그리고, 관절이 들어간 띠와 몸통 숙임(30°)을 조합 표에 넣음
- `overlay_floor.py`(개선 1): 회전체 다각형 + 설비 앞 바닥선. 발목에서 바닥선까지 거리(키 1.6m로 축척 추정)가 1.0m 안이고 손목이 회전체와 겹치면 정지, 1.0m 안이면 감속, 2.0m 안이면 주의

## 결과

| | 정지 | 감속 | 주의 | 반응 없음 |
|---|---|---|---|---|
| trim_7 개선 전 (180프레임) | 156 | 2 | 3 | 19 |
| trim_7 개선 1 (180프레임) | 151 | 7 | 4 | 18 |

- 질문 1: 화면은 의도대로 만들어졌다. 포즈 중앙값 149ms, 규칙 0.2ms (CPU)
- 질문 2·3: 판단할 수 없다. 개선 1을 붙여도 결과가 거의 같았고, 아래 이유로 둘 다 믿을 수 없다

## 실패 원인

1. **깊이를 모른다 (근본 원인).** 작업자는 롤 앞에 서 있지만 2D 화면에서는 몸이 롤과 겹친다. 위험한계를 평면 다각형으로 그리는 한 "롤 앞에 서 있음"과 "롤에 손을 댐"을 구별할 수 없다. 실험 02·03과 같은 문제다.
2. **편집본이라 카메라가 고정되어 있지 않다.** 클립 사이는 물론 한 클립 안에서도 확대 비율이 바뀐다. 고정해 둔 위험한계와 바닥선이 어긋났다(t=4.0s에 발이 떨어져 있는데 거리 0.0m).
3. **위험한계를 사람이 눈으로 그렸다.** 회전체 다각형의 아래 끝이 작업자 허리 높이와 거의 맞닿아, 손목이 10px만 흔들려도 판정이 바뀌었다. 정답 기준이 없어 그린 선이 맞는지 검증할 방법도 없다.
4. **정답이 없다.** 프레임마다 "이 순간 정답 단계는 무엇인가"를 미리 정하지 않았으므로 맞고 틀림을 셀 수 없다.
5. **추정값이 섞였다.** 키 1.6m, 내려다보는 각도 보정 0.65, 팔이 닿는 거리 1.0m는 모두 재지 않은 값이다.

## 결정 (2026-10-16)

- 위험한계는 **설치할 때 사람이 설정**한다. 처음 보는 설비에서 자동으로 찾는 것은 다음 단계로 둔다.
- 깊이 문제는 러닝머신 촬영에서 **카메라를 롤러 축 방향(옆)에 두는 것**으로 피한다.
- 성능 근거는 변인을 통제한 러닝머신 시험 영상으로만 낸다: 고정 카메라, 줄자로 잰 구역, 촬영 전에 정한 장면별 정답, 한 번에 변수 하나만 바꿈.
- 현장 사고 영상은 "실패 사례와 한계"로만 보고한다. 편집되지 않은 고정 CCTV 원본을 구하면 개선 1을 다시 시험한다.
