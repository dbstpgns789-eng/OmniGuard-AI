# 05. 현장 사고 CCTV 사례 연구: 접촉 전에 정지가 뜨는가

## 질문

손이 회전체에 처음 닿는 시점(Tc) 전에 정지 신호가 뜨는가. 바닥 기준 거리(V2)가 화면상 겹침만 보는 방식(V1)보다 접근 전 오정지를 줄이는가.

## 조건 (실행 전에 정함)

- 영상: 사용자가 화면 녹화한 사고 CCTV 2개 (레포 밖 `OmniGuard-data/raw_cctv/`)
  - `rec_001918`: 야간 녹색 고정 CCTV, 종이 롤 설비. 4.0~18.5초 사용, Tc = 15.0초 (양손이 롤 표면에 닿음)
  - `rec_002103`: 롤 권취기(빨간 상의 작업자), 편집으로 화면이 옆으로 최대 250px 이동. 7.0~46.5초 사용(뒤쪽은 같은 장면 반복), Tc = 37.0초. 화면 이동은 배경 특징점으로 재서 구역을 따라 옮김(V1·V2 공통)
- Tc는 0.5초 간격 프레임을 보고 정함. 불확실성 ±0.5초
- 바꾸는 변수 하나: V1 손목이 회전체 다각형과 겹치면 정지 / V2 발이 설비 앞 바닥선에서 1.0m 안 + 손목 겹침이면 정지, 1.0m 안이면 감속, 2.0m 안이면 주의
- 고정: rtmlib `Body` lightweight(CPU), 신뢰도 0.3, 정지 연속 확인 3프레임, 구역은 기준 프레임에서 한 번만 그림, 포즈는 프레임마다 한 번만 추정해 두 규칙에 같이 넣음
- 측정: 선행 시간 = Tc − [Tc−3초, Tc] 안의 첫 정지 시각 / 접근 전 오정지 비율 = Tc−3초 이전 프레임 중 정지 비율

## 결과 (`result.json`, `*_frames.csv`)

| 영상 | 방식 | 선행 시간 | Tc±0.5초 정지 비율 | 접근 전 오정지 비율 |
|---|---|---|---|---|
| rec_001918 | V1 | 1.57초 | **0.00** | 0.75 |
| rec_001918 | V2 | 1.57초 | **0.00** | 0.75 |
| rec_002103 | V1 | 1.23초 | 0.61 | 0.10 |
| rec_002103 | V2 | 1.23초 | 0.61 | 0.10 |

- 처음 정한 "Tc에서 이어지는 정지 구간의 시작" 기준으로는 두 영상 모두 값이 나오지 않았다. 정지가 프레임마다 깜빡여 연속 구간이 끊기기 때문이다. 그래서 위 표는 창 안의 첫 정지로 다시 계산한 값이다(실행 후 바꾼 기준임을 밝혀 둔다).
- V2는 두 영상 모두 V1과 정지 결과가 같았다. 다른 점은 V2가 정지 대신 감속을 오래 띄운 것이다(rec_002103에서 감속 721/1185프레임).

## 해석

1. **rec_001918의 "선행 1.57초"는 성공이 아니다.** 13.4초의 정지는 작업자가 롤 앞을 걸어갈 때 화면상 겹쳐서 뜬 것이고, 정작 손이 닿은 15~17초에는 정지가 한 프레임도 없었다. 야간 화면에서 몸을 숙인 어두운 옷의 작업자를 포즈 모델이 놓쳤고, 대신 설비 기둥을 사람으로 잘못 잡았다. 사람 검출률 1.0도 이 잘못 잡은 "사람" 때문에 부풀려진 값이다.
2. **rec_001918의 V2는 제대로 시험되지 않았다.** 바닥선을 실제 바닥보다 아래에 그려서 발이 늘 선 "안쪽"(거리 0.0m)으로 계산됐다. 위험한계를 사람이 그리는 방식의 약점이 다시 드러났다.
3. **rec_002103에서는 거리만으로 정상 작업과 위험 행동을 구별할 수 없었다.** 이 작업자는 평소 일하는 위치 자체가 설비에서 0.3~1.0m였다. 그래서 V2는 내내 감속을 띄웠고, 오정지를 줄이지 못했다. 정상 작업과 위험 행동을 가르는 것은 거리가 아니라 **손이 회전체 쪽으로 움직이는 동작**이었다. 조합 표의 ② 위험 동작(느린 경로)이 필요한 이유가 여기서 나온다.
4. 사고가 2건뿐이고 Tc를 사람이 정했으므로 사례 연구다. 수치를 일반화하지 않는다.
