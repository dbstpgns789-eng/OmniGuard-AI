# OmniGuard AI 작업 정리 (2026-10-15 ~ 10-16)

> 컴퓨터비전을 막 배우기 시작한 사람도 읽을 수 있게 썼다. 용어는 처음 나올 때 풀어서 설명한다.

## 한 줄 요약

"무엇을 증명할지"를 먼저 정했고, 실제 사고 영상으로 실험해 보면서 **카메라 한 대의 평면 화면으로는 깊이를 알 수 없다는 한계**와 **거리보다 손의 움직임이 중요하다는 사실**을 확인했다. 그래서 성능 평가는 우리가 직접 통제해서 찍는 러닝머신 영상으로 하기로 했다.

---

## 1. 이 프로젝트가 하려는 것

> '사람의 신체(손, 팔)'를 완벽하게 찾는 사전 학습 모델을 가져온 뒤, 기하학적 연산(Rule-based Logic)을 덧붙여 사고를 정의하는 것입니다.

컨베이어 벨트에 작업자의 몸이 말려 들어가는 사고를 막고 싶다. 카메라가 작업자를 계속 보다가, 몸이 위험한 곳에 가까워지면 **주의 → 감속 → 정지** 신호를 낸다.

### 설비와 위험한 곳

- **설비:** 컨베이어 벨트. 시연에서는 러닝머신을 컨베이어로 본다.
- **위험한 곳:** 벨트 한가운데가 아니라, **컨베이어 끝에서 벨트가 롤러에 감겨 들어가는 부분**이다. 컨베이어는 양 끝의 롤러에 벨트가 감겨서 돌고, 러닝머신도 뒤쪽 끝에 같은 롤러가 있다.
- 현장 사고 영상에 롤 권취기나 종이 롤 기계가 나오는 것은, "돌아가는 롤에 감겨 들어간다"는 원리가 같아서 참고로 쓴 것이다.

### 카메라 영상이 신호로 바뀌는 과정

```
① 사람 탐지    화면 속 사람을 네모 상자로 찾는다
      ↓
② 포즈 추정    그 사람의 관절 17개 좌표를 찾는다
      ↓
③ 규칙 판단    관절이 위험한 영역에 들어갔는지 보고 단계를 정한다
      ↓
④ 신호         주의 / 감속 / 정지
```

- ①과 ②는 이미 학습된 모델(사람 탐지 모델, RTMPose)을 그대로 쓴다. 우리가 직접 만드는 것은 ③의 규칙뿐이다.
- 관절 17개에는 손목뿐 아니라 **발목**과 **머리(코·눈·귀)**도 들어 있다. 실제로 공개 사고 영상(iSafetyBench)에는 작업자가 벨트 위를 걷다가 **끝 롤러에 발이 끼인 사고가 13건** 있었다. 그래서 손목만 볼지, 다른 부위도 볼지는 실험으로 정한다(아래).
- **옷자락과 머리카락은 관절이 아니라서 포즈 모델로 볼 수 없다.** 실제 사고 중에는 소매나 머리카락이 먼저 감기는 경우가 많으므로, 이것은 한계로 남긴다.

### 모델을 튜닝하지 않아도 되나

조건에 따라 다르다.

| 조건 | 사전학습 모델 그대로 | 근거 |
|---|---|---|
| 밝고, 사람이 크게 보이고, 가리는 것이 없음 | 충분하다 | 실험 01: 공장 CCTV 100프레임 중 98프레임에서 사람을 찾음 |
| 야간, 몸을 숙임, 어두운 옷 | 부족하다 | 실험 05: 손을 댄 순간 작업자를 놓치고, 설비 기둥을 사람으로 잘못 잡음 |
| 몸이 설비 안으로 들어감 | 부족하다 | 실험 03: 관절이 가려져 신뢰도가 0.14~0.16으로 떨어짐 |

- **시연:** 러닝머신 촬영은 조명과 카메라 위치를 우리가 정하므로 첫 번째 조건에 해당한다. 튜닝 없이 충분할 가능성이 높고, 촬영 후 "관절 신뢰도 0.3 이상인 프레임 비율"로 확인한다.
- **실제 공장:** 튜닝이 필요하다. 그러려면 야간이나 몸을 숙인 작업자 사진에 관절 위치를 표시한 학습 데이터가 있어야 하는데, 지금은 없다. 그래서 "현장 조건에서는 튜닝이 필요하다"를 한계이자 다음 단계로 둔다.

### 어느 부위를 판단에 넣을지 (실험으로 정함)

- 손목만 보면 발 끼임과 머리 숙임을 놓친다.
- 관절 전부를 보면, 작업자가 롤 앞에 서 있기만 해도 화면에서 몸 전체가 위험 영역과 겹쳐 **오정지가 크게 늘 것으로 예상한다**(실험 04·05에서 본 2D 겹침).
- 그래서 두 방식을 같은 영상에 돌려 비교한다(실험 06).

## 2. 오늘 정한 것

결정이 내려진 순서대로 적는다.

| 순서 | 결정 | 왜 |
|---|---|---|
| ① | 시연 설비는 **컨베이어 벨트**(러닝머신), 위험한 곳은 **끝 롤러에 벨트가 감겨 들어가는 부분** | 발표 피드백에서 범위가 넓다는 지적이 있었고, 강사가 "롤러 쪽 자료가 많다"고 했다 |
| ② | **학습하지 않는다** | 사람 탐지와 포즈 추정은 사전학습 모델로 충분하고(밝은 조건, 1장 참고), 우리가 만드는 것은 판단 규칙이다 |
| ③ | 목표는 **시험 장면 8개에 맞게 반응 + 정지 신호까지 0.3초 이내 + 기준선 대비 개선** | 0.3초는 외부 기업 수치가 아니라 팀이 PR/FAQ에서 정한 목표값이다. 기준선은 우리 영상에서 다시 잰다 |
| ④ | 평가 데이터는 **러닝머신 영상 8장면 × 5회 = 40개** | 정답을 우리가 미리 정할 수 있는 유일한 데이터다. 공개 데이터 중에는 컨베이어 끼임 장면에 정답이 붙은 것이 없다 |
| ⑤ | **A·B·C안 비교**: A 지금 그대로(기준선) / B 속도 최적화 / C VLM | 강사가 "A·B·C안을 테스트해 보고 정하라"고 했다 |
| ⑥ | VLM은 **정지를 결정하지 않고**, 몇 초마다 "정비하려는 중인가"를 판단하는 느린 경로에 둔다 | VLM은 한 번 답하는 데 수 초가 걸린다. 그 사이 손은 이미 롤러에 닿는다 |
| ⑦ | 위험 수준은 **조합 기준**(가동 여부 × 몸의 위치 × 위험 동작) | 세훈이 먼저 골랐고, 실험 05에서 "거리만으로는 정상 작업과 위험 행동을 구별할 수 없다"는 결과로 근거가 확인됐다 |
| ⑧ | 위험한계는 **닿으면 끝인 영역**이고, 정지는 그보다 안전 거리만큼 바깥에서 낸다 | 돌아가는 롤러에 손이 닿으면 이미 늦다 |
| ⑨ | 위험한계는 **설치할 때 사람이 설정**한다 | 처음 보는 설비에서 자동으로 찾는 것은 다음 단계다 |
| ⑩ | 시연은 **녹화 영상**으로 한다 | 강사: 라이브 시연 불필요 |
| ⑪ | 역할: 앞단(탐지·포즈·구역)과 A·B·C 측정은 세훈 + Claude, 위험 수준 판정 이후와 보고서는 채우 | |

## 3. 용어 정리

| 용어 | 쉬운 설명 |
|---|---|
| 회전체 | 돌고 있는 롤, 드럼, 벨트. 어디에 닿아도 감겨 들어갈 수 있다 |
| 맞물림부 | 회전체가 다른 부품과 맞닿아 빨려 들어가는 선. 가장 위험한 곳 |
| 위험한계 | **닿으면 끝인 영역** (회전체 표면 + 맞물림부). 시스템이 제대로 동작하면 사람이 닿지 않아야 한다 |
| 안전 거리 | 정지 신호를 낸 뒤 기계가 완전히 멈출 때까지 손이 움직이는 거리. 손 속도 2m/s × (판단 시간 + 기계 정지 시간) |
| 정지·감속·주의 구역 | 위험한계 바깥에 차례로 놓인 구역. 정지 구역은 위험한계에서 안전 거리만큼 바깥까지 |
| 빠른 경로 | 매 프레임 규칙으로 바로 판단하는 길. **정지는 항상 여기서 결정**한다 |
| 느린 경로 | VLM이 몇 초마다 "이 사람이 정비하려는 중인가"를 판단하는 길. 빠른 경로를 기다리게 하지 않는다 |
| 기준선 | 지금 파이프라인을 우리 영상에 돌려서 얻은 결과. 개선했다고 말할 때 비교하는 출발점 |
| 끼임 거리 | 두 부품 사이 틈이 몸을 눌러 끼우지 않도록 **설비를 설계할 때** 확보하는 간격(예: 손가락 25mm). 설비 구조의 문제라서, 이 시스템이 다루는 안전 거리와 다르다 |
| 접근 속도 | 손이 움직이는 속도 중 **회전체 쪽을 향하는 성분**만 뽑은 값. 옆으로 지나가거나 물러나는 움직임은 0에 가깝다 |
| TTC (Time To Contact) | 지금 접근 속도가 유지될 때 손이 위험한계에 닿기까지 남은 시간. 거리 ÷ 접근 속도. 짧을수록 위험하다 |
| 오정지와 놓침 | 오정지: 위험하지 않은데 멈춘 것. 놓침: 위험한데 멈추지 않은 것. **한쪽을 줄이면 다른 쪽이 늘어나는 관계**라서 항상 둘을 함께 보고한다(실험 06: 관절 전부를 보면 놓침은 줄고 오정지는 늘었다) |

왜 정지 경로에 VLM을 넣지 않나? VLM이 한 번 답하는 데 수 초가 걸린다. 그 사이 손은 이미 롤러에 닿는다.

```
시간   빠른 경로 (매 프레임)               느린 경로 (VLM, 몇 초마다)
0.0초  먼 구역 진입 → 주의
0.5초                                     "롤러를 청소하려는 중" → 위험 동작 표시
1.2초  가까운 구역 + 위험 동작 → 감속
1.5초  정지 구역 → 즉시 정지 (VLM을 기다리지 않음)
2.0초                                     이유 기록 "가동 중 청소 시도" → 안전관리자
```

## 5. 오늘 한 실험

### 실험 03: 사고 직전 캡처 12장에 규칙 돌리기

- **질문:** 손목-구역 규칙이 실제 사고 직전 장면에서 반응하는가
- **결과:** 12장 중 8장 반응. 하지만 제대로 잡은 것은 4장뿐이었다.
- **배운 것:** 몸이 설비 안으로 들어갈수록 관절이 가려져 포즈 추정이 실패한다. 정지 화면 한 장으로는 "몇 초 전에 경고했나"를 잴 수 없다.

### 실험 04: 사고 영상에 주의·감속·정지 화면 얹기 (탐색)

- **질문:** 상상한 화면(영상을 보다가 주의 → 감속 → 정지)이 실제로 만들어지는가
- **결과:** 화면은 만들어졌다(포즈 149ms, 규칙 0.2ms, 노트북 CPU). 하지만 처음부터 끝까지 거의 "정지"만 떴다.
- **실패 원인:**
  1. **깊이를 모른다.** 작업자가 롤 **앞에** 서 있을 뿐인데 평면 화면에서는 롤과 겹쳐 보인다.
  2. 뉴스 편집본이라 화면이 확대·이동해서, 고정해 둔 구역이 어긋났다.
  3. 구역을 눈으로 그려서 정확하지 않았다.
  4. 프레임마다 정답을 미리 정하지 않아 맞고 틀림을 셀 수 없었다.
- **반성:** 변인을 통제한 실험이 아니었다. 이후 실험은 질문, 정답 기준, 바꾸는 변수 하나, 예상을 **먼저 적고** 돌리기로 했다.

### 실험 05: 사고 CCTV 2건에서 "닿기 전에 멈추는가"

- **설계 (실행 전에 정함):**
  - 정답: 손이 회전체에 처음 닿는 시점(Tc)을 프레임을 보고 표시
  - 바꾸는 변수 하나: V1 "손목이 화면상 회전체와 겹치면 정지" vs V2 "발이 설비에서 1m 안이고 손목이 겹칠 때만 정지" (바닥 기준 거리)
  - 같은 포즈 결과를 두 규칙에 똑같이 넣음
- **결과:**

| 영상 | 접촉 순간에 정지 | 걸어가기만 할 때 잘못 정지 |
|---|---|---|
| 야간 종이 롤 | 0% (놓침) | 75% |
| 빨간 상의 롤 권취기 | 61% | 10% |

  V1과 V2의 결과가 같았다.
- **실패 원인:**
  1. 야간 영상에서 몸을 숙인 작업자를 포즈 모델이 놓치고, 설비 기둥을 사람으로 잘못 잡았다.
  2. 바닥선을 잘못 그려서 V2가 제대로 시험되지 않았다.
  3. **가장 중요한 발견:** 빨간 상의 작업자는 평소 일하는 위치 자체가 설비에서 0.3~1.0m였다. 그래서 거리로는 정상 작업과 위험 행동을 구별할 수 없었다. 둘을 가르는 것은 **손이 회전체 쪽으로 움직이는 동작**이었다. 조합 기준의 "위험 동작"이 필요한 이유가 실제 사고 영상에서 확인됐다.

기록: `experiments/03_nip_refs/`, `04_overlay_demo/`, `05_field_cases/`의 README

## 7. 오늘 실패에서 배운 것 세 가지

1. **평면 화면은 깊이를 모른다.** 롤 앞에 서 있는 것과 롤에 손을 댄 것이 똑같이 보인다. → 카메라를 롤러 옆(축 방향)에 두면 화면 거리와 실제 거리가 비례한다.
2. **거리보다 움직임이다.** 작업자는 원래 설비 가까이에서 일한다. 위험은 "가까이 있음"이 아니라 "손이 회전체 쪽으로 향함"이다.
3. **통제하지 않은 실험은 아무것도 증명하지 못한다.** 그래서 성능 수치는 고정 카메라, 줄자로 잰 기준선, 미리 정한 정답이 있는 러닝머신 영상으로만 낸다.
