# OmniGuard AI 발표 원고 (논리 순서, 채우 전달용, 2026-10-21)

> **Claude에게 (이 원고로 슬라이드를 만들 때 지켜 주세요)**
> - 목적: 컴퓨터비전 학부 과제 OmniGuard AI의 발표 슬라이드. 심사 기준 7개(1 데이터 EDA·전처리, 2 모델 탐색·선정, 3 성능 향상의 논리, 4 여러 시도, 5 결론의 설득력, 6 Metric 설정·근거·분석, 7 발표)에 맞춰 장을 구성했다
> - 숫자는 **이 원고에 적힌 것만** 쓴다. 없는 숫자를 만들거나 반올림해 바꾸지 않는다
> - 순서는 이 원고의 장 순서(데이터 → 모델 → 기준선과 지표 → 다듬기 → 시험 → 결론 → 다음)를 따른다. 실험 번호(괄호)는 근거 확인용이라 슬라이드에는 넣지 않아도 된다
> - 원고에 없는 실험이나 한계 문구를 새로 넣지 않는다. 표현은 "평가 데이터셋 구축", "규칙 기반 기준선(baseline)", "하이퍼파라미터 그리드 서치", "후처리", "학습·검증·시험 분리", "소프트웨어 1.0 → 2.0"을 그대로 쓴다
> - 판단기 결과를 얹은 데모 영상과 추가 실험(정상 동작만으로 배우는 이상 탐지, 약한 라벨로 데이터 늘리기) 결과는 나중에 보완된다


실험은 날짜 순서로 진행했지만, 발표는 **데이터 → 모델 → 기준선과 지표 → 다듬기 → 시험 → 결론 → 다음** 순서로 재구성했다.
각 장마다 **심사 기준 번호**, **핵심 메시지**, **근거 숫자**, **그림 자료**를 적었다. 괄호 안의 "실험 NN"은 근거를 찾아볼 때만 쓰고, 슬라이드에는 넣지 않아도 된다.

심사 기준: 1 데이터 EDA·전처리 / 2 모델 탐색·선정 / 3 성능 향상의 논리 / 4 여러 시도 / 5 결론의 설득력 / 6 Metric 설정·근거·분석 / 7 발표

## 큰 줄거리 (한 장)

> **소프트웨어 1.0으로 끝까지 가 보고, 그 한계를 숫자로 확인했다. 그 과정에서 2.0으로 가는 데 필요한 데이터셋과 평가 방법을 만들었다.**

1. 사전학습 비전 모델로 사람과 관절은 잘 찾는다 (인식)
2. 그 위에 규칙 기반 기준선(baseline)을 세우고, 오류 분석과 하이퍼파라미터 탐색으로 다듬었다 (소프트웨어 1.0)
3. 모델을 고정하고 처음 보는 사고로 시험하자, 개발 데이터에 많이 맞춘 모델일수록 일반화가 떨어졌다
4. 원인은 카메라 한 대(2D)의 한계: 비전 모델은 "사람이 어디 있나"는 알지만 "롤 앞에 서 있나, 롤에 들어가나"는 모른다 (인식과 상황 이해 사이의 빈칸)
5. 다음: 데이터에서 배우는 모델(시간 모델, VLM)과 3D (소프트웨어 2.0)

## 1장. 문제와 목표

- **문제:** 회전체(롤 맞물림부, 롤러, 회전축)에 손·옷·머리카락이 끼이는 사고. 끼임은 제조업 사망 원인 상위이고, 현장에서는 방호장치를 제거해 사고가 난다
- **목표:** 공장 CCTV로 사람이 회전체에 닿기 **전에** 정상 → 주의 → 정지 신호를 낸다
- **성공 기준:** 사고 직전 정지율은 지키면서(목표 99~100%), 평소에 괜히 멈추는 헛정지를 줄인다. 헛정지가 잦으면 현장에서 장치를 꺼 버리기 때문이다
- **시나리오:** 관리자가 CCTV 화면에서 위험한계(회전체 영역)를 한 번 그려 두면, 시스템이 그 영역을 기준으로 판단한다

## 2장. 데이터: 평가 데이터셋을 직접 구축했다 (기준 1, 6)

### 2-1. 공개 데이터 탐색 (EDA)
- 공장 안전 공개 데이터(Safe and Unsafe Behaviours, 691개 영상, 시점 3개, 라벨 8종)를 분석: **라벨이 영상 하나에 하나뿐**이다. 한 영상에 사람 여럿, 설비 여럿, 시간 흐름이 있는데 "누가·어느 설비에서·언제"를 나누지 않는다. 사고 장면은 없다 (실험 02)
- GitHub·Kaggle·Hugging Face 전체 조사: **"닿기 직전" 끼임 장면이 있는 공개 데이터는 iSafetyBench의 사고 하나뿐**이었다 (`docs/research/12_open_datasets.md`)
- 그래서 **사고 데이터는 직접 모으고, 정상 데이터는 공개 데이터에서 찾았다**
  - 사고: 웹 사고 영상 61개 목록 → 53개 수집 → 화질·고정 카메라·사람 크기·접근 과정 기준으로 6개 + 유튜브 SafeGuard Accidents 채널에서 녹화 13개 = **사고 19건**
  - 정상: Safe and Unsafe에서 롤러 설비 근처 평소 작업 14개(약 2분)를 찾아 헛정지 시험용으로 씀 (실험 11)

### 2-2. 라벨 정의와 판단 기준
- 처음에는 "손이 닿았나"를 정답으로 하려 했지만, CCTV 화면으로는 닿았는지 알 수 없는 경우가 많았다 → **라벨 질문을 "지금 기계를 멈춰야 하나"로 정의** (실험 08)
- **판단 기준을 만들고 → 평가 데이터셋을 구축했다.** 무엇을 보면 정상·주의·정지인지 글로 정했다(정지 = 사고를 막아야 하는 예방 시점). 0.2초 간격 프레임마다 단계, 닿은 순간, 판단 이유(메모)를 적는다 (`docs/판단기준.md`)
- **판단자 2명**(세훈·채우)이 서로 상의하지 않고 같은 영상을 판단해 라벨의 품질과 신뢰도를 확인했다. 두 사람은 같은 순간을 위험의 시작으로 봤다(정지 시작 차이 중앙값 0.2초) (실험 15)
- 단계는 회의에서 정상·주의·정지 3개로 정했다

### 2-3. 위험한계 그리기
- 관리자 시나리오대로 사람이 영상마다 롤 양 끝 원판을 그리면, 두 원판을 감싸는 영역이 위험한계가 된다. 그리기 도구를 직접 만들었다(판단기가 보는 영역을 실시간으로 색칠해 보여 줌)
- **위험한계를 사람이 정확히 그리기만 해도 판단이 크게 좋아졌다** (4단계 macro F1 0.53 → 0.65, 실험 09)
- 그림: `OmniGuard-data/세훈_작업/위험한계_확인.jpg`(20개 영상의 위험한계), `그리기_예시.jpg`

### 2-4. 전처리
- **편집 구간 제외:** 웹 영상의 제목 화면, 컷, 전환 구간은 채점에서 뺀다
- **화면 보정:** 화면 녹화·재촬영 영상이 흔들려서, 위험한계를 그린 기준 화면에 매 프레임을 맞춘다(ORB 특징점 + RANSAC 호모그래피). 위험한계가 카메라를 따라 움직인다
- **포즈 품질 필터:** 사람이 아닌 것(설비)을 사람으로 잡거나 관절이 화면을 가로질러 튀는 검출을 거른다. 팔·다리 한 마디가 몸통 길이의 1.5배보다 길면 그 관절을 버리고, 보이는 관절이 6개 미만이거나 평균 신뢰도가 0.4 미만이면 사람으로 보지 않는다 (실험 28)
- **개발·검증·시험 데이터 모두 같은 전처리**를 거쳤다

### 2-5. 데이터 분할
| 용도 | 데이터 | 쓰임 |
|---|---|---|
| 개발 | 빨간 상의 사고(iSafetyBench), 사고 5건, 프레스 평소 작업 14개 | 기준선을 만들고 다듬음 |
| 검증(맞춤) | 사고 9건 (화면 10개) | 고칠 후보를 고름 |
| 시험 | 사고 10건 | 점수만 잼, 장면은 열지 않음 |
- 검증·시험은 결과를 보기 전에 **무작위로** 나눴다 (실험 20)

## 3장. 모델: 사전학습 비전 모델 탐색과 선정 (기준 2)

### 3-1. 왜 사전학습 모델인가
- 학습 없이도 공장 고정 CCTV에서 **사람을 100프레임 중 98프레임** 찾았다 (실험 01)
- 반면 사고 데이터가 적어서, 영상 하나로 학습한 분류기는 같은 영상에서 0.94였지만 **학습에 안 쓴 구간에서 0.51**(4단계 macro F1)로 떨어졌다 (실험 09) → 학습 대신 **사전학습 모델 + 규칙 기준선**으로 출발

### 3-2. 모델 비교
| 역할 | 고른 모델 | 비교한 모델과 결과 | 고른 근거 |
|---|---|---|---|
| 관절 | RTMPose performance (rtmlib, OpenVINO) | lightweight: 야간 작업자 4% 탐지 | performance는 67% 탐지 (실험 07) |
| 손 | 몸 관절의 손목 | MediaPipe Hands: CCTV에서 손을 하나도 못 찾음 (손이 너무 작음) | (실험 07) |
| 사람 윤곽 | YOLO11n-seg | - | 관절로 안 보이는 옷을 잡음: 헐렁한 옷이 롤에 다가가는 순간을 2.5초 일찍 잡음 (실험 16) |
| 깊이 | 쓰지 않음 | 단안 깊이 모델 12개 조사, Depth Anything V2 Small 적용 | 실내 오차 약 10cm라 손-롤 몇 cm를 못 가름. "사람이 롤보다 앞인가"로 바꿔 적용해도 사고 순간에도 사람은 롤 앞에 있어 실패 (실험 23) |

### 3-3. 시간 흐름을 배우는 모델 (소프트웨어 2.0 시도)
규칙 대신, 최근 1초의 관절 흐름을 한꺼번에 입력해 "지금 정지가 필요한가"를 데이터에서 배우게 했다. 학습은 검증용 사고 9건 + 평소 작업, 시험은 처음 보는 사고 10건 (실험 24·25)

| 모델 | 검증 데이터 교차 검증 | 처음 보는 사고 정지율 | 1분당 헛정지 |
|---|---|---|---|
| 그래디언트 부스팅 (관절 기하 값 × 6시점) | 6/10 | 7/10 | **4.8** |
| 로지스틱 회귀 (관절 기하 값) | 9/10 | 8/10 | 5.7 |
| **MotionBERT** (ICCV 2023, 사전학습 모션 트랜스포머, 인코더 고정 + 분류 층만 학습) + 기하 값 | **10/10** | 6/10 | 6.7 |
| (비교) 규칙 기준선 + 정지 유지 | - | 9/10 | 7.6 |

- **학습 모델은 헛정지가 더 적었다** (4.8~6.7/분 vs 규칙 7.6/분)
- **MotionBERT는 규칙이 못 잡던 신호를 잡았다:** 다른 모든 모델이 놓친 사고(드럼 맞물림부에 종이를 넣다 끌려 들어감)를 "넣는 동작"으로 잡았다. 검증 데이터에서는 10/10으로 가장 좋았다
- 다만 사고 9건으로 학습해서 처음 보는 사고에서는 6/10 → **데이터가 늘면 가장 먼저 좋아질 모델**
- 모델 출력은 프레임마다 깜빡여서, 학습 모델에도 정지 유지 후처리가 필요했다

### 3-4. 속도
| 설정 | 프레임당 시간 (CPU) |
|---|---|
| 가벼운 모델, onnxruntime | 176ms |
| + OpenVINO | 68ms |
| + 사람 탐지 5프레임마다 | **17ms** |
| 큰 모델(performance) | 약 900ms |
| 단안 깊이 모델 | 670~1550ms |
| MotionBERT 인코더 (1초 시계열 하나) | 약 180ms |
- 정확도를 위해 고른 큰 모델은 실시간보다 약 30배 느리다 → 가벼운 모델로 바꿨을 때 얼마를 잃는지가 다음 과제

### 3-5. 모델의 한계: 가장 위험한 순간에 함께 놓친다
- 몸이 설비 안으로 들어가는 순간 관절이 가려진다 (실험 03 사고 직전 캡처)
- 처음 보는 사고 시험에서도 사고 직전에 포즈가 사람을 놓쳤고(A09, D08), **같은 순간 사람 윤곽 모델도 함께 놓쳤다** (실험 21·22)
- 원인: 학습 데이터(COCO 계열)에 드문 공장 시점·숙인 자세·뒷모습 + 가림 + 움직임 흐림 + 화질. 두 모델의 사각지대가 겹친다

## 4장. 규칙 기준선과 지표 (기준 3, 6)

### 4-1. 기준선 구조
사전학습 모델이 찾은 관절 위에 판단 규칙을 얹은 기준선(baseline):
- **거리:** 관절과 위험한계 사이 거리를 그 사람의 몸통 길이 단위로 잰다 (카메라마다 사람 크기가 달라도 같은 기준)
- **시간 흐름:** 사진 한 장이 아니라 관절의 궤적을 본다. 사람은 "걷는가"보다 **"어느 방향으로 걷는가"**를 보고 위험을 판단했다 → 발목 궤적으로 설비 쪽으로 다가오는지, 나란히 지나가는지를 계산 (실험 09)
- **후처리:** 모델 출력은 프레임마다 깜빡이므로 그대로 믿지 않는다. 정지는 바로 걸고, 해제는 사람이 위험한계 근처를 벗어난 상태가 이어질 때 한다(히스테리시스, 현장 안전 정지·리셋 방식)

### 4-2. 지표를 이렇게 정했다
- 처음에는 4단계(정상·주의·감속·정지) macro F1을 썼다
- 같은 사고의 다른 화면(iSafetyBench 클립)에 기준선을 그대로 옮기자 **macro F1은 0.80 → 0.46으로 떨어졌지만, 사고 전에 정지는 하나도 놓치지 않았고 정상에서는 한 번도 멈추지 않았다.** 틀린 것은 한 단계 더 조심한 것(감속 → 정지)뿐이었다 (실험 10)
- → 모든 틀림을 똑같이 벌하는 지표는 안전 장치에 맞지 않는다. **지표를 바꿨다:**

| 지표 | 정의 | 왜 |
|---|---|---|
| **정지율** | 닿기 0.5초 전부터 닿을 때까지 정지가 켜져 있었나 (사고 수 중 몇 건) | 사고 한 번이 치명적. 롤러 기계는 멈추는 데 0.75~1.5초가 걸려 미리 멈춰야 함 |
| **헛정지 (횟수)** | 정상 구간에서 정지가 켜진 횟수, 1분당 | 헛정지가 잦으면 장치를 꺼 버림 |
| **헛정지 (시간)** | 정상 구간 중 정지가 켜져 있던 시간 비율 | 무조건 멈추는 모델도 정지율은 100%라서, 정지율은 반드시 평소 정지 시간과 함께 봐야 함 (실험 22) |

## 5장. 기준선 다듬기 (기준 3, 4)

### 5-1. 깊게 잡으면 놓치고, 얕게 잡으면 멈춘다
| 기준선 | 처음 보는 사고 5건 | 평소 작업 헛정지 |
|---|---|---|
| 한 영상에 맞춘 깊은 정지 기준 | 2/5 | 0.5/분 |
| **원칙 기준** (어떤 영상에도 맞추지 않음: 위험한계 경계에 닿으면 정지) | **4/5** | 약 5/분 |
- 정지 기준값을 어디에 둬도 이 맞교환이 남았다. 원인은 기준값이 아니라 **화면의 겹침이 진짜인지 모른다**는 것 (실험 11·12·13)
- 이 원칙 기준이 나중에 처음 보는 사고에서 가장 잘 버틴 모델이 된다

### 5-2. 헛정지를 줄이는 시도
| 시도 | 결과에서 얻은 것 |
|---|---|
| 연구를 따라 발 위치로 겹침 거르기 (ISO 13855로 1m) | 헛정지를 낸 사람은 지나가는 사람이 아니라 **손 닿는 거리에서 일하는 작업자**였다 (실험 14) |
| 안전해 보이는 자세(꼿꼿함)면 정지 해제 | 사고 직전에도 정지가 풀렸다 → **"정지를 풀 때는 '안전해 보이는가'가 아니라 '위험한 곳에서 떠났는가'를 봐야 한다"** → 6장의 정지 유지로 (실험 14) |
| 손이 롤 안으로 들어갔다는 단서 (팔이 짧아 보임, 손이 사라짐) | 팔이 짧아 보이는 것은 롤 쪽으로 뻗을 때와 설비 위에 손을 얹을 때 똑같고, 손이 사라지는 것은 롤 뒤로 들어갈 때와 몸 뒤로 가려질 때 똑같다 → **2D에서 뽑은 단서는 2D의 모호함을 그대로 물려받는다** (실험 17) |
| 옷 윤곽 (YOLO11n-seg) | 헐렁한 옷이 걸릴 듯한 순간을 2.5초 일찍 잡음 (실험 16) |

### 5-3. 하이퍼파라미터 그리드 서치
- 기준선의 하이퍼파라미터 6개: 정지 거리 7 × 단계 간격 3 × 몸만 들어와도 정지 2 × 정지 유지 시간 2 × 옷 신호 2 × 가림 확인 2 = **336가지**
- 같은 개발 데이터로 모두 채점 → 모든 지표에서 밀리는 조합을 빼고(24개 남음) 대표 3개를 고름 (실험 18)
- **개발 데이터 최고 조합("조용한 안"): 평소 헛정지 0회**
- 좋은 조합에는 모두 정지 유지 1초가 들어 있었다 (후처리의 근거)
- 정지 거리를 표준처럼 바깥으로 넓히면 사고는 더 안 잡히고 헛정지만 늘었다 (2D에서는 화면상 가까움 ≠ 실제 가까움)

### 5-4. 오류 분석
- 원칙(관절 17개 중 하나라도 닿으면 정지)에서 출발 → 헛정지 장면마다 원인 관절을 기록 → **원인 9번 모두 상체(2D 겹침), 발·무릎은 0번** → 가장 큰 원인부터 고침: 발이 설비 앞선 바깥이면 상체 겹침 무시 (실험 19)
- **개발 데이터 헛정지 9 → 1회, 사고 4/4 유지**

## 6장. 처음 보는 사고로 시험 (기준 5)

### 6-1. 평가 방법
모델과 평가 코드를 시험 전에 커밋으로 고정하고, 시험 데이터는 점수를 잴 때 한 번만 열었다 (실험 20)

### 6-2. 결과: 개발 데이터에 많이 맞출수록 일반화가 떨어졌다
| 모델 | 개발 데이터 | **처음 보는 사고 (20개 화면)** |
|---|---|---|
| 원칙 기준 | 사고 4/4 | **정지 13/20** |
| 오류 분석으로 다듬은 기준 (규칙 4) | 사고 4/4, 헛정지 0.5/분 | 10/20 |
| 그리드 서치 최고 조합 (조용한 안) | 헛정지 0회 | 2/20 |
- 오류 분석과 그리드 서치로 개발 데이터를 다듬을수록 그 데이터에 맞춰졌다 (검증 데이터 과적합). **이것이 소프트웨어 1.0의 한계였다** (실험 21)

### 6-3. 후처리로 정지율을 올림
- 원칙 기준에 **정지 유지 후처리**를 더함: 한 번 걸린 정지는 사람이 위험한계 근처를 벗어난 상태가 1초 이어질 때까지 유지, 포즈를 놓치면(모르는 상황) 유지 (실험 22)
- 검증 데이터로 후보 3개 중 고르고, 시험 데이터에 한 번 → **시험 정지율 5/10 → 9/10**
- 여기에 **포즈 품질 필터**를 더한 것이 **최종 판단기**: 시험 정지율 8/10, 1분당 헛정지 7.6 → **5.7**, 평소 정지 시간 67% → 64%. A04 카펫 롤러는 평소 정지 0%로, 평소에는 한 번도 안 멈추다 닿기 전에 멈췄다 (실험 28)
- 다만 평소에 멈춰 있는 시간도 54% → 67%로 늘었다. 평소에는 안 멈추다 사고 직전에 멈춘 것이 2건(A04 카펫 롤러, D12), 평소에도 거의 계속 멈춘 것이 4건 → **위험을 잡을수록 오래 멈춘다**

### 6-4. 데모 영상 추천
- **A04 카펫 롤러** (시험용, 처음 본 영상): 평소 작업 → 롤러 앞 작업 → 끌려감이 고정 CCTV로 선명하게 보이고, 평소에는 거의 안 멈추다 사고 직전에 멈춘 경우
- 최종 판단기 결과를 얹은 데모 영상: `2_데모영상/데모_A04_carpet.mp4` (화면 위 = 판단기 상태와 이유, 아래 = 판단기·정답 시간 막대)
- 한계 데모(7장): `데모_D09.mp4`, `데모_B38_mixer.mp4`, `데모_red.mp4`. 롤 앞에서 일하기만 해도 화면에서 겹쳐 멈추는 모습

## 7장. 결론: 카메라 한 대(2D)의 한계 (기준 5)

> **카메라 한 대의 화면은 "롤 앞에 서 있는 사람"과 "롤에 들어가는 사람"을 구별하지 못한다.** 비전 모델은 사람이 어디 있는지는 알지만, 그 겹침이 실제로 위험한지는 모른다(인식과 상황 이해 사이의 빈칸).

손잡이를 바꿔 가며 반복해도 같은 벽이 나왔다:
| 바꾼 것 | 결과 |
|---|---|
| 정지 기준값 | 깊게 잡으면 놓치고 얕게 잡으면 멈춤 |
| 하이퍼파라미터 336가지 | 헛정지 0이면 놓치고, 더 잡으면 헛정지 |
| 오류 분석으로 규칙 추가 | 개발 데이터에서는 좋아지고 처음 보는 데이터에서는 떨어짐 |
| 관절에서 뽑은 단서 | 2D의 모호함을 그대로 물려받음 |
| 단안 깊이 | 사고 순간에도 사람은 롤 앞에 있음, 필요한 것은 손끝-롤 몇 cm |
| 다른 사전학습 모델 | 가장 위험한 순간에 함께 놓침 |
| 정지 유지 후처리 | 정지율은 올랐지만 평소에도 오래 멈춤 |

- **사람도 화면만 보지 않는다:** 판단자는 "2D로 보이는 것을 공간으로 상상해서" 판단했다. 판단기에는 그 정보가 없다
- **업계도 같다:** 국내 업체(세이지)도 협착 오탐의 원인으로 "화면상 겹침"을 꼽고 깊이 지도를 쓴다. 상용 제품은 맞물림부 정지를 깊이 카메라나 카메라 2대로 한다
- **2D 기준선의 쓸모:** 위험의 시작은 사람보다 3~4초 일찍 보고, 정지 유지로 사고를 놓치지 않는 쪽으로 동작한다 → 더 정확한 장치가 확인하기 전에 먼저 거는 **1차 안전층**

## 8장. 다음: 소프트웨어 2.0과 3D (기준 5, 7)

### 8-1. 이미 만든 것
판단 기준을 정한 평가 데이터셋(약 30개 영상, 0.2초 라벨, 위험한계), 학습·검증·시험 분리, 지표. **같은 시험 데이터로 다음 모델을 바로 비교할 수 있다.**

### 8-2. 데이터에서 배우는 모델: 첫걸음을 이미 뗐다
- 최신 사전학습 모션 모델(MotionBERT)로 "정지가 필요한가"를 배우게 해 봤다(3-3). 규칙이 못 잡던 "넣는 동작"을 잡았고 헛정지도 적었다. 사고 9건으로는 처음 보는 사고까지 일반화하지 못했다
- **병목은 모델이 아니라 데이터 양**이다. 그동안 만든 평가 데이터셋 구축 방식(판단 기준, 0.2초 판단표, 위험한계 그리기 도구)이 그대로 데이터를 늘리는 방법이 된다. 데이터가 늘면 MotionBERT 같은 사전학습 모델을 미세조정해 규칙 기준선을 넘는 것이 다음 목표
- **VLM (채우): 1차 판단기 → 2차 VLM 확인.** 데모 영상 4개의 0.2초 프레임을 채우의 두 모델(jev, vlm)로 판단해 세훈 판단표로 채점했다
  | 영상 | 최종 판단기 (평소 정지) | vlm (평소 정지) | 닿기 직전 정지 |
  |---|---|---|---|
  | A04 | 0% | 0% | 둘 다 함 |
  | B38 | 100% | **62%** | 둘 다 함 |
  | D09 | 96% | **36%** | 둘 다 함 |
  | 빨간 상의 | 100% | **64%** | - |
  - 최종 판단기는 정지를 하나도 놓치지 않으므로, **판단기가 1차로 정지를 걸고 VLM이 2차로 확인**하면 정지는 지키면서 평소 정지를 줄일 수 있다. 업계(세이지)의 1차 탐지 → VLM 2차 확인 구조와 같다
  - jev는 평소에 거의 안 멈췄지만 사고 2건(A04, B38)을 놓쳤다

### 8-3. 3D: 카메라를 어디에, 몇 대 (세훈)
- 문제는 판단 규칙이 아니라 **카메라의 자리**였다. 비스듬히 내려다보는 CCTV는 하필 "롤에서 얼마나 떨어져 있나"를 잃는다
- **배치:** 맞물림부를 위나 롤 축 방향 옆에서 보는 카메라 추가. 두 카메라 사이 각도 60~90°
- **다중 카메라 합성:** 렌즈 보정(ChArUco) → 카메라끼리 위치 맞추기 → **시간 맞추기**(손 속도 2m/s면 한 프레임 어긋남 = 약 6.6cm 오차) → 관절 삼각측량 → 롤을 3D로 한 번 측정 → 손끝-롤 표면 거리로 판단. 이론 오차 mm~1cm
- **단계:** 단기(기존 CCTV = 1차 경고층, 가벼운 모델) → 중기(맞물림부 카메라 1~2대, 3D 판단) → 장기(기계 정지 신호 연결, 헛정지 시간 예산)
