# 발표에 넣을 실험 고르기 (세훈과 하나씩 확인, 2026-10-21~)

기준
- **남김:** 설계가 탄탄하고 인사이트가 프로젝트 흐름에 꼭 필요함
- **합침:** 혼자서는 약하지만 다른 실험과 묶으면 근거가 됨
- **뺌:** 대충 설계했거나, 정답을 Claude가 정했거나, 결론이 나중에 뒤집혀 그대로 보여 주기 어려움

| 실험 | 결정 | 발표에서 쓸 인사이트 (세훈 확인) | 쓰지 않을 것과 이유 |
|---|---|---|---|
| 01 | **짧게 남김** (모델 선정 슬라이드의 한 줄) | 밝은 고정 CCTV(터키 프레스 공장, 파란 프레스·주황 설비)라면 사전학습 모델이 학습 없이도 사람과 관절을 충분히 잡는다는 것을 눈으로 확인했다 (사람 98/100프레임) | 자세 한 장으로 개입/통행 73%: 영상 하나에 라벨 하나인 데이터라 믿기 어려움 |
| 02 | **합침** (숫자 빼고 인사이트만) | ① **데이터 EDA:** 공개 데이터 구성 분석(영상 691개, 시점 3개, 라벨 8종) → 라벨이 영상 하나에 하나뿐(사람·설비·순간 단위가 아님), 사고 장면 없음 → 그래서 0.2초 판단표를 직접 만듦. 대신 롤러 설비 근처 평소 작업 14개를 찾아 헛정지 시험용으로 용도를 다시 정함(→ 실험 11) ② **2D 겹침을 처음 인지한 실험:** 설비 뒤의 사람도 화면에서는 구역 안처럼 보임 (사진 한 장) | 66.7%: 위험 구역을 Claude가 눈대중으로 그렸고(관리자가 그리는 시나리오와 다름), 정답이 영상 단위 라벨. 프레스는 회전체가 아님 |

**공통 원칙(세훈, 10-21):** 시나리오는 "관리자가 화면을 보고 경계를 그린다". Claude가 그린 위험 구역으로 낸 숫자는 발표에서 쓰지 않는다.
