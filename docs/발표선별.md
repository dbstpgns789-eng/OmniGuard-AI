# 발표에 넣을 실험 고르기 (세훈과 하나씩 확인, 2026-10-21~)

심사 기준(각 10점): 1 데이터 EDA·전처리 / 2 모델 탐색·선정 / 3 성능 향상의 논리 / 4 여러 시도 / 5 결론의 설득력 / 6 Metric 설정·근거·분석 / 7 발표
**심사 기준에서 거꾸로 보고, 그 기준에서 점수를 받을 수 있는 것만 남긴다.**

## 이야기 틀 (세훈 확인, 10-21)
"AI 없던 시절의 규칙 시스템"처럼 보이지 않도록 이렇게 말한다.

| 피할 표현 | 쓸 표현 | 기준 |
|---|---|---|
| 사람의 판단을 정답으로 썼다 | **평가 데이터셋을 직접 구축했다**: 0.2초 단위 3단계 라벨링 규칙(`docs/판단기준.md`), 판단자 2명, 일치도 측정 | 1, 6 |
| 사람의 이유를 규칙으로 옮겼다 | **사전학습 비전 모델의 인식 결과 위에 규칙 기반 기준선(baseline)을 세웠다** → 그 기준선이 어디서 무너지는지 측정했다 | 3, 5 |
| 규칙의 한계 | **인식(perception)과 상황 이해(understanding) 사이의 빈칸**을 정량으로 보였다. 비전 모델은 "사람·관절이 어디 있나"는 알지만 "무엇을 하려는 중인가, 그 겹침이 실제로 위험한가"는 모른다 → 상황 이해 모델(VLM, 채우)과 3D(세훈)가 필요한 이유 | 5, 7 |

## 큰 줄거리: 소프트웨어 1.0 → 2.0 (세훈, 10-21)
카파시의 구분: 1.0 = 사람이 규칙을 짠다, 2.0 = 데이터에서 모델이 규칙을 배운다.
1. **1.0으로 끝까지 가 봄:** 사전학습 비전 모델 위에 규칙 기준선, 오류 분석(19)·하이퍼파라미터 그리드 서치(18)로 다듬음
2. **1.0의 한계를 숫자로 확인:** 개발 데이터에서 다듬을수록 처음 보는 사고에서 떨어짐(원칙 13/20 > 규칙 4 10/20 > 조용한 안 2/20, 21). 사람이 규칙으로 옮길 수 있는 것은 2D 정보뿐이고 2D는 앞뒤를 구별 못 함(5장)
3. **2.0에 필요한 것을 이미 만듦:** 판단 기준을 정한 평가 데이터셋(약 30개 영상, 0.2초 라벨, 위험한계), 학습·검증·시험 분리, 지표
4. **다음:** 데이터에서 배우는 모델(여러 프레임을 넣는 시간 모델, VLM 채우, 3D 세훈)

## 고르는 원칙 (세훈, 10-21)
- **원칙 1:** 시나리오는 "관리자가 화면을 보고 경계를 그린다"(처음 기획부터). Claude가 그린 위험 구역으로 낸 숫자는 쓰지 않는다
- **원칙 2:** 정량 지표는 제대로 설계한 실험부터 말한다. 그 전 실험은 인사이트만
- **원칙 3:** 뒤에 같은 인사이트를 제대로 보여 주는 실험이 있으면 앞 실험은 과감히 뺀다
- 결정: **남김** / **합침**(숫자 없이 인사이트만 다른 곳에 녹임) / **뺌**

- **발표 순서 (세훈, 10-21):** 실험 번호(날짜) 순서가 아니라 논리 순서로 재구성한다. 선별이 끝나면 남긴 내용을 데이터 → 모델 → 논리·시도 → 결과·설득력 → 지표 → 다음 단계 순으로 배치

## 선별 뒤 후보 실험
- **골격 기반 행동 인식 vs 규칙 기준선:** 사전학습 골격 행동 모델(ST-GCN, PoseC3D 등)의 특징 + 마지막 층만 판단표로 학습, 영상 하나 빼고 학습·평가(교차 검증). 같은 시험 영상에서 J13·C1과 정지율·헛정지 비교. 근거: 판단표 있는 영상이 이제 약 30개, 세훈 질문 "어느 방향으로 걷는지 모델이 어떻게 알게 하나". 한계: 입력이 같은 2D 관절이라 2D 겹침은 남음. 기준 2(모델 탐색)

- **여러 프레임을 모델 입력으로 (세훈 관심, 나중에 다룸):** 프레임 건너뛰기는 속도용(07, 탐지 5프레임마다)으로 이미 씀. 여러 프레임 결과를 모아 판단하는 것도 판단기 안에 있음(다가오는 속도, 걷는 방향, 다수결). **여러 프레임을 한꺼번에 모델 입력으로 넣는 시간 모델은 안 해 봄** → 골격 행동 인식 후보와 같은 방향. 다수결 vs 정지 유지 비교도 후보(정지 유지는 "걸 때 빠르게, 풀 때 느리게" 비대칭이라 골랐음)
- **말하는 방식 (세훈, 10-21):** 머신러닝·딥러닝 전문가처럼 말한다. 예: 336가지 조합 → 기준선 하이퍼파라미터 6개 그리드 서치, 정지 유지 → 모델 출력을 그대로 믿지 않는 후처리(디바운스·히스테리시스), 조용한 안의 실패 → 검증 데이터 과적합, 판단기 고정·시험 분리 → 학습·검증·시험 분리

- **✅ 전처리 맞추기 완료 (10-21):** 개발 데이터에도 같은 화면 보정 적용, 카메라 이동 0px(고정 카메라)라 결과 그대로. 이제 모든 데이터에 같은 전처리. (원래 메모: 전처리는 개발·검증·시험 데이터에 똑같이 해야 한다. 지금은 시험 영상만 화면 보정을 켜고, 개발 사고 5건(12)은 끄고 돌렸다 → 개발 데이터에도 같은 화면 보정을 켜고 다시 채점(포즈는 있음). 그러면 "모든 데이터에 같은 전처리(편집 구간 제외, 화면 보정)"라고 말할 수 있다)
- **ROC·PR 곡선은 발표에서 뺀다 (세훈):** 정지율·헛정지 두 숫자로 충분. 질문이 나오면 꺼낼 예비 자료로만
